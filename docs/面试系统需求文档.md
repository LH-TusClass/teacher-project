## 1. 项目概述

### 1.1 背景
当前招聘面试流程依赖邮件、电话与线下表格管理，存在面试安排混乱、候选人信息分散、面试评价缺乏标准化、流程数据无法沉淀等问题。需要建设一套面试系统，实现从候选人申请、面试安排、面试执行到结果评估的全流程线上化管理。

### 1.2 项目目标
- 全流程线上化：申请 → 简历筛选 → 面试安排 → 面试执行 → 评价打分 → 结果决策。
- 角色分工明确：管理员、HR、面试官、候选人各司其职。
- 数据可沉淀：面试记录、评价、报告可查询、可统计。
- 架构前后端分离，便于独立开发、部署与扩展。

### 1.3 项目范围
**本期包含：**
- 候选人端（Web/H5）：注册登录、简历管理、职位申请、面试通知、结果查询、在线面试入口。
- 管理端（PC Web）：职位管理、候选人管理、申请管理、面试安排、面试执行与评价、题库与在线笔试（可选）、Offer 管理、统计报表、系统管理（用户/角色/权限/字典/日志）。

**本期不含（预留扩展）：**
- 移动 App（iOS/Android）。
- 智能简历解析（AI 提取结构化信息）。
- 面试录音/录像的语音识别与转写。
- 多租户 SaaS 化。

### 1.4 名词解释
| 名词 | 说明 |
| --- | --- |
| 候选人 | 注册并申请职位的求职者 |
| HR | 负责招聘流程推进的人员 |
| 面试官 | 被指派执行某场面试的人员 |
| 面试轮次 | 候选人同一职位可能经历多轮面试（电话面/一面/二面/终面等） |
| 题库 | 系统内按分类、难度组织的题目集合 |
| 笔试 | 候选人在线作答的系统化考试 |
| Offer | 通过面试后向候选人发出的录用通知 |

## 2. 用户角色与权限

| 角色 | 主要职责 | 核心权限 |
| --- | --- | --- |
| 超级管理员 | 系统配置与维护 | 用户/角色/权限/字典管理，全部功能 |
| HR（招聘专员） | 招聘流程推进 | 职位、候选人、申请、面试安排、Offer、报表 |
| 面试官 | 执行面试并评价 | 查看分配给自己的面试任务、简历材料，提交评分与评价 |
| 候选人 | 求职方 | 注册、维护简历、申请职位、查看面试通知与结果（独立账号体系，入口与后台分离） |

权限要求：
- 后台采用 RBAC 模型（用户-角色-菜单/按钮权限）。
- 面试官只能访问与其相关的面试数据，不可见其他候选人敏感信息。
- 候选人数据（手机号、身份证号等）需脱敏展示，仅授权角色可见明文。

## 3. 总体业务流程

主流程（以"申请 → 入职"为主线）：

```
候选人注册/登录
      │
      ▼
维护简历 → 浏览职位 → 提交申请
      │
      ▼
HR 简历筛选 ──不通过──▶ 流程终止（发送感谢信）
      │ 通过
      ▼
安排面试（轮次、时间、面试官、方式：现场/视频/电话）
      │
      ▼
候选人确认/改约（可选）
      │
      ▼
面试执行（到场签到 / 进入视频面试间）
      │
      ▼
面试官提交评分 + 评价意见
      │
      ▼
HR 汇总决策 ──淘汰──▶ 流程终止
      │ 通过
      ▼
(可选) 在线笔试 / 加面
      │
      ▼
发放 Offer → 候选人接受/拒绝
      │
      ▼
流程归档，数据入报表
```

关键规则：
- 同一候选人同一职位可有多轮面试，轮次按序推进，前轮未通过则后续轮次自动取消。
- 面试安排前系统校验面试官时间冲突（与已有面试/日程重叠则提示）。
- 面试开始前需候选人确认；超时未确认 HR 可人工催办。
- 任一环节状态变化均生成通知（站内消息 + 邮件/短信，邮件短信可配置为可选）。

## 4. 功能需求

### 4.1 候选人端（Web/H5）

#### 4.1.1 注册与登录
- 支持手机号 + 短信验证码注册/登录；支持账号密码登录。
- 忘记密码通过手机号重置。
- 同一手机号仅一个候选人账号；登录 token 过期后自动跳转登录页。

#### 4.1.2 简历管理
- 基本信息：姓名、性别、出生年月、手机号、邮箱、现居住地、求职意向（期望职位/城市/薪资）。
- 工作经历：公司名称、岗位、起止时间、工作内容（支持多条）。
- 教育经历：学校、专业、学历、起止时间（支持多条）。
- 项目/技能/证书：自由文本 + 附件。
- 简历附件上传：支持 PDF/Word，单个文件 ≤ 10MB。
- 简历提交后锁定关键字段（期望职位等），可解锁重新编辑（记录变更日志）。

#### 4.1.3 职位申请
- 职位列表：按名称/城市/部门筛选，展示要求与薪资范围。
- 查看详情并一键申请；已申请职位标注状态（已投递/筛选中/面试中/已通过/已淘汰）。
- 同一职位 7 天内不可重复投递。
- 申请人可查看每个申请的处理进度（时间线形式）。

#### 4.1.4 面试通知与确认
- 收到面试邀请：展示职位、轮次、时间、方式、地点/入会链接、面试官（可仅显示部门+称谓）。
- 操作：确认参加 / 申请改约（填写期望时间段，HR 处理）/ 取消并说明原因。
- 面试前 24 小时、2 小时各提醒一次（站内 + 可选邮件/短信）。

#### 4.1.5 在线面试（视频）
- 通过面试页"进入面试间"链接加入视频会议。
- 要求：面试前检测摄像头/麦克风；面试中不可挂起；系统记录实际入场时间。
- 技术方案：一期对接第三方实时音视频（如腾讯云 TRTC / LiveKit 自部署），系统负责鉴权与链接管理。

#### 4.1.6 结果查看
- 申请最终结果：通过 / 未通过（脱敏文案，不展示具体评分）。
- Offer 详情：岗位、部门、薪资结构、报到时间、合同说明；操作接受 / 拒绝。

### 4.2 管理端 - 招聘模块（HR/管理员）

#### 4.2.1 职位管理
- 职位 CRUD：名称、所属部门、城市、招聘部门、需求人数、薪资范围、任职要求、职位描述、状态（招聘中/暂停/已关闭）。
- 职位与面试模板关联：可配置该职位默认面试轮次（如 电话初筛 → 一面 → 二面 → 终面）。
- 关闭职位后不再接受新申请，进行中的申请可继续处理。

#### 4.2.2 候选人管理
- 候选人列表：姓名、手机号、期望职位、最近活跃、来源；支持按状态/职位筛选、关键字搜索。
- 候选人详情：基本信息、简历（在线查看 + 附件下载）、申请记录时间线、面试记录、笔试记录。
- 手动添加候选人（线下简历录入场景）。
- 敏感字段脱敏，授权角色可一键查看明文（记操作日志）。

#### 4.2.3 申请管理
- 申请列表：候选人、职位、当前环节、状态、进入当前环节时间。
- 状态流转操作（按当前环节）：
  - 简历筛选：通过 / 不通过（必填原因，原因入字典）。
  - 面试后：通过 / 不通过 / 待讨论（可批量操作）。
- 每个状态变更写入申请时间线，可回看全部操作人、时间与原因。
- 筛选支持：按职位、按环节、按时间段、按处理人。

#### 4.2.4 面试安排
- 新建面试：选择候选人 + 职位申请、轮次、日期时间、时长、方式（现场/视频/电话）、面试官（可多人，需全部接受后生效）、地点或生成入会链接、备注。
- 日历视图：按日/周展示所有面试，支持拖拽改期；改期自动通知候选人和面试官。
- 冲突校验：同一面试官同时段多场面试则告警；同一候选人同时段多场面试则禁止保存。
- 面试状态：待接受 → 待面试 → 进行中 → 已完成 / 已取消 / 已爽约。
- 面试官可"接受/改期申请"；候选人可"确认/改约"。
- 现场面试支持生成签到二维码（候选人扫码签到，记录到场时间）。

#### 4.2.5 Offer 管理
- 创建 Offer：基于已通过的申请，填写岗位、部门、薪酬结构、试用期、报到时间、备注。
- 发送后候选人可见并接受/拒绝；HR 可撤回未接受的 Offer。
- Offer 状态：草稿 → 已发送 → 已接受 / 已拒绝 / 已过期 / 已撤回。

#### 4.2.6 统计报表
- 招聘漏斗：各职位各环节人数与转化率（申请 → 筛选 → 各轮面试 → 通过 → Offer → 接受）。
- 部门/职位维度：平均招聘周期（申请到入职天数）、面试量、通过率。
- 面试官维度：面试场次、平均评分、评价响应时长（提交评分距面试结束时长）。
- 导出：列表数据支持导出 Excel。

### 4.3 管理端 - 面试官模块

#### 4.3.1 面试日程
- 我的面试列表/日历：仅展示分配给自己的面试（含候选人姓名与职位，简历需点击"查看材料"授权访问并记日志）。
- 状态：待接受 / 待面试 / 进行中 / 已完成 / 已取消。

#### 4.3.2 面试材料
- 查看候选人简历（在线 + 附件）、申请进度、历史轮次评价（前轮通过后才可发起后续轮）。
- 系统提示前轮未通过则锁定本轮发起。

#### 4.3.3 面试执行
- 视频面试：进入面试间链接（同候选人端）；面试结束由 HR 或系统按结束时间自动结束。
- 现场面试：支持面试官在管理端"开始/结束"计时。
- 超时保护：视频面试超过约定时长 30 分钟未结束自动提醒。

#### 4.3.4 评分与评价
- 面试结束后 24 小时内必须提交（超时提醒，超时 48 小时升级提醒 HR）。
- 评分表：按职位可选评价维度（默认模板：专业能力、项目经验、沟通表达、文化匹配、学习能力，各维度 1-5 分），总分自动计算，可附综合评语（必填 ≥ 20 字）。
- 结论：推荐录用 / 待定 / 不推荐（"待定"需 HR 跟进）。
- 提交后不可修改；如需修改由 HR 发起并记录修改原因。

### 4.4 题库与在线笔试（一期可选，建议纳入二期）

> 若一期不做，保留题库管理即可，笔试执行放二期。以下按"完整实现"描述。

#### 4.4.1 题库管理
- 题型：单选、多选、判断、简答、编程题（代码框 + 语言选择）。
- 题目属性：题干、选项、正确答案（客观题）、难度（简单/中等/困难）、所属分类（技术栈/行为面等）、解析。
- 支持批量导入（Excel 模板）。
- 题目状态：草稿 / 已发布 / 已废弃；仅已发布题目可入卷。
- 题目查重：保存时基于题干相似度给出重复提示。

#### 4.4.2 组卷
- 手动组卷：从题库勾选题目。
- 随机组卷：按分类 + 难度 + 题量规则随机抽取。
- 试卷属性：名称、适用职位/岗位、总时长、总分、是否允许中途退出（退出后不可再考）、可考次数。
- 防作弊（基础）：答题页禁止复制粘贴与右键、切屏超过 3 次标记异常、IP + 设备指纹限制。

#### 4.4.3 在线考试
- 候选人端答题：倒计时、题号导航、自动保存（每次操作 + 每 60s 心跳）。
- 断线保护：断线 10 分钟内可续答，否则按交卷处理。
- 交卷：客观题即时自动判分；主观题待面试官/HR 人工评分。
- 成绩：笔试总分展示在候选人详情与申请时间线；低于可配置分数线自动建议"不通过"。

### 4.5 系统管理

#### 4.5.1 用户与组织
- 后台用户 CRUD：工号/账号、姓名、手机、邮箱、所属部门、启用/停用。
- 部门树：支持两级以上部门管理。
- 首次登录强制修改初始密码。

#### 4.5.2 角色与权限（RBAC）
- 角色 CRUD，菜单权限 + 按钮权限两级控制。
- 内置角色：超级管理员、HR、面试官；支持自定义角色。
- 权限变更即时生效（下一次请求校验，或 5 分钟内失效缓存）。

#### 4.5.3 字典管理
- 通用字典：学历、血型、面试方式、淘汰原因、评价结论、题目难度等。
- 字典项 CRUD，被引用后不可删除（只能停用）。

#### 4.5.4 消息通知
- 站内消息中心：未读角标、分类列表、标记已读。
- 触发动作：面试邀请、改约、催办、Offer、结果通知等。
- 通道：站内必选；邮件/短信可选（对接邮件网关/短信服务商），发送失败进入重试队列（最多 3 次）。
- 通知模板管理：可编辑文案变量（候选人姓名、时间、链接等）。

#### 4.5.5 操作日志与审计
- 记录：谁、何时、何 IP、对何数据做了何操作（增删改查关键动作、导出、敏感字段查看）。
- 日志保留 ≥ 180 天；敏感字段明文查看全部留痕。
- 日志列表支持按用户/模块/时间检索。

## 5. 非功能需求

### 5.1 性能
- 常规列表接口 P95 响应时间 ≤ 500ms（10 万级候选人数据量下）。
- 日历视图数据加载 ≤ 1s。
- 支持并发：视频面试高峰期 200 路并发音视频信令，1000 用户同时在线。
- 报表查询（漏斗/维度聚合）≤ 3s，超 3s 需走异步 + 结果缓存。

### 5.2 可用性
- 核心服务（面试安排、面试执行、消息通知）可用性目标 99.9%。
- 数据库每日全备 + binlog 增量；RPO ≤ 1h，RTO ≤ 4h。
- 依赖第三方（音视频/短信）故障降级：视频不可用时面试可降级为电话/现场，不影响流程记录。

### 5.3 安全
- 全站 HTTPS；接口鉴权使用 JWT（访问 2h + 刷新 7d）。
- 密码 BCrypt 加盐存储；连续 5 次失败锁定 15 分钟。
- 候选人 PII 数据（手机号、身份证）入库 AES 加密存储，库表备份加密。
- 防越权：接口级数据权限（面试官仅本人数据；HR 按授权范围）；防 CSRF、XSS（前端转义 + 后端 Content-Security-Policy）。
- 接口限流：登录 5 次/分/账号；文件下载按用户限流。
- 敏感操作（导出、查看明文）二次确认 + 审计。

### 5.4 兼容性
- 浏览器：Chrome / Edge / Firefox 最近两个大版本；分辨率 ≥ 1366×768。
- 候选人 H5：iOS Safari 15+、Android Chrome 90+；视频面试需桌面端体验为主（移动端可仅用于查看与确认）。

### 5.5 可维护性与可扩展
- 前后端完全分离，通过 REST API 交互；接口版本化（/api/v1/...）。
- 后端模块化（招聘域、面试域、题库域、系统域），接口契约先行。
- 日志统一接入（traceId 贯穿前后端）。
- 预留开放接口：与 HRM/ATS 同步职位与候选人（二期）。

## 6. 技术方案

### 6.1 总体架构（前后端分离）

```
┌─────────────────────┐   ┌─────────────────────┐
│  管理端 (PC Web)    │   │  候选人端 (Web/H5)  │
│  Vue 3 + Element Plus│  │  Vue 3 (H5 适配)    │
└──────────┬──────────┘   └──────────┬──────────┘
           │        HTTPS / JSON     │
           ▼                         ▼
   ┌──────────────────────────────────────────┐
   │  Nginx（静态资源 + 反向代理 + 限流）      │
   └──────────────────┬───────────────────────┘
                      ▼
   ┌──────────────────────────────────────────┐
   │  Java 后端服务 (Spring Boot)             │
   │  - 认证鉴权 (JWT)  - 招聘域  - 面试域    │
   │  - 题库域          - 通知域  - 系统域     │
   └───┬──────────┬──────────┬──────────┬─────┘
       ▼          ▼          ▼          ▼
   MySQL 8    Redis      对象存储     第三方
   (主数据)  (缓存/会话) (MinIO/OSS)  (音视频/短信/邮件)
```

### 6.2 前端
| 项 | 选型 | 说明 |
| --- | --- | --- |
| 框架 | Vue 3（组合式 API）+ TypeScript | Vite 构建 |
| 状态管理 | Pinia | 用户信息、权限字典、消息未读 |
| 路由 | Vue Router | 路由级权限守卫 |
| UI 组件 | Element Plus（管理端）/ Vant（候选人 H5） | 日历用组件或封装 |
| 请求 | Axios | 拦截器统一 token 注入、刷新、错误处理 |
| 图表 | ECharts | 报表漏斗与趋势 |
| 其他 | 全端 TS、ESLint + Prettier | 代码规范统一 |

工程结构建议（monorepo 两个 package 或两个仓库）：
- `interview-admin`：管理端（HR/管理员/面试官）
- `interview-candidate`：候选人端（Web/H5 自适应）

### 6.3 后端
| 项 | 选型 | 说明 |
| --- | --- | --- |
| 语言/运行时 | Java 17 | LTS |
| 框架 | Spring Boot 3.x | 单体模块化起步（domain 分包），预留拆服务 |
| 持久层 | MyBatis-Plus + MySQL 8 | 数据源 HikariCP |
| 缓存 | Redis 7 | token 黑名单、字典缓存、日历数据、限流计数 |
| 安全 | Spring Security + JWT | 双 token（access/refresh），RBAC 数据权限 |
| 校验 | Jakarta Validation | 入参校验统一 |
| 文档 | SpringDoc (OpenAPI 3) | 接口文档，前后端契约 |
| 任务 | Spring Task / XXL-Job | 面试提醒、超时处理、报表预聚合 |
| 文件 | MinIO（自建）或云 OSS | 简历、附件 |
| 音视频 | 腾讯云 TRTC 或 LiveKit（自部署） | 仅做信令与链接管理，鉴权由后端签发 |
| 日志 | SLF4J + Logback + MDC(traceId) | 统一格式 |

代码分层约定：`controller`（接口/参数校验）→ `service`（业务与事务）→ `mapper`（数据访问），DTO/VO 与实体分离，统一异常处理 + 统一响应体。

### 6.4 部署
- 开发/测试：Docker Compose 一键拉起（MySQL、Redis、MinIO、后端、前端 Nginx）。
- 生产：
  - 前端：Nginx 容器/静态站，按路径分发 admin / candidate 两套构建产物。
  - 后端：JDK17 容器（可 2 副本），Nginx 负载均衡，会话无状态（Redis 存公共态）。
  - 数据库：主从 + 每日备份；Redis 单实例起步（开启 AOF）。
- 环境：dev / test / staging / prod 四套；接口统一网关域名 + `/api/v1` 前缀。

## 8. 接口规范

- 风格：RESTful，路径 `/api/v1/{module}/{resource}`，资源用名词，动作用 HTTP 方法表达。
- 统一响应体：

```json
{ "code": 0, "message": "ok", "data": { ... } }
```

- 错误码约定：`0` 成功；`1xxxx` 参数/业务错误；`401` 未认证；`403` 无权限；`5xxxx` 系统错误。
- 鉴权：`Authorization: Bearer <accessToken>`；刷新接口 `POST /api/v1/auth/refresh`。
- 分页：`?pageNum=1&pageSize=20`，响应 `data: { list, total, pageNum, pageSize }`。
- 时间：统一 ISO-8601（`yyyy-MM-dd'T'HH:mm:ss`）+ 时区 GMT+8。
- 文件上传：`POST /api/v1/files`（multipart），返回文件 key 与访问 URL（私有资源走带 token 的临时 URL）。
- 主要接口示例：
  - 登录：`POST /api/v1/auth/login`（候选人/后台分端参数或分路径）
  - 职位：`GET /api/v1/positions`、`POST /api/v1/positions`
  - 申请：`POST /api/v1/applications`、`POST /api/v1/applications/{id}/advance`
  - 面试：`GET /api/v1/interviews/calendar?year=&month=`、`POST /api/v1/interviews`、`PUT /api/v1/interviews/{id}`（改期）
  - 评价：`POST /api/v1/interviews/{id}/evaluations`
  - 报表：`GET /api/v1/reports/funnel?positionId=&from=&to=`
  - 题库/笔试：`/api/v1/questions`、`/api/v1/exam-papers`、`/api/v1/exam-records/{id}/submit`
